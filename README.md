# 宠物陪伴 Agent · 有长期记忆的微信小程序

微信小程序 + Python 后端。这里的 Agent（智能体：由模型驱动、按固定流程完成一轮任务的程序）围绕一条完整的长期记忆链路：把用户原话提炼成可溯源、可纠正、可删除的记忆，按宠物隔离；对话以流式输出，记忆抽取与消解交给可恢复的后台任务。

## 一、项目概览

用户打开小程序 → 微信登录 → 选择预设宠物「团子」或创建一只自定义宠物 → 进入聊天。再次进入时恢复上次选择的宠物；每只宠物拥有独立的记忆域与对话上下文。

### 核心不变量

| 不变量 | 实现 |
| --- | --- |
| 记忆按 `pet_id` 隔离 | 过滤条件在召回前就带进向量检索的过滤字段与关键词检索的语料范围，不在应用层事后剔除 |
| 一人一宠一段会话 | 会话身份由 `(user_id, pet_id)` 唯一确定，每只宠物一条连续会话 |
| AI 只提议 | 模型输出提议（Proposal：模型给出、尚未被系统接受的候选动作），由 `settle()` 结算成提交计划（CommitPlan：一次对话最终要执行的副作用清单） |
| 终态不可逆 | 一次对话运行（Run：从受理到终态的执行记录）到达 `succeeded / failed / cancelled` 后不再变化 |
| 副作用幂等 | 每个副作用（Effect：写库、建索引等对外部世界的改变）都带幂等键（`idempotency_key`：同一个键重复执行只生效一次） |

## 三、系统结构

![架构](docs/architecture.svg)

| 组件 | 职责 |
| --- | --- |
| 微信小程序 | 4 个页面；用 `wx.request` 的分片回调接收流式回复 |
| H5 调试台（网页调试客户端） | `/demo`：复用同一套 API 与事件流的浏览器页面 |
| API 进程（接口服务） | FastAPI：受理 Run、推进事件流、限流与取消 |
| Worker 进程（后台任务进程） | 后台慢活：记忆抽取、三判定消解、索引投影，不阻塞用户回复 |
| MySQL 8 | 账号、宠物档案 |
| MongoDB 7 | 会话消息、记忆、出处、事件、任务队列 —— 权威数据 |
| Qdrant | 向量索引 —— 可重建投影 |
| Redis 7 | 限流计数、短期运行状态、使用计数缓冲 |
| 阿里云百炼 | 对话 / 向量（1024 维）/ 立绘与表情素材（离线生成） |

**权威数据与投影分离**：MongoDB 保存不可再生的原文、记忆与出处，Qdrant 只保存可由记忆重建的向量索引。删除一条记忆时，权威记录与向量投影必须同时清理；索引丢失时，可以从权威数据重建。这条约束决定了"删除"是否真的生效。


### 3.1 身份与数据隔离

`wx.login()` 只产出一枚一次性 `code`（临时登录码，5 分钟内有效且只能使用一次）。后端用 AppID + secret 调用微信 `jscode2session` 换取 `openid`，映射为内部 `user_id`，再签发 HMAC-SHA256（带密钥的哈希签名：客户端改内容后算不出新签名）保护的 Bearer Token（持有者令牌：客户端每次请求携带的身份凭证，默认 7 天有效）。令牌只包含 `user_id`、签发时间与过期时间，不携带 `openid`；服务端验签并校验过期后才进入业务层。

所有面向用户的资源查询都带 `user_id`，并在仓储层校验归属；归属不匹配时统一按不存在处理。当前宠物指针持久化在用户记录上，进入时恢复"最后聊的那只"；写入与检索都以 `pet_id` 为作用域，记忆不会跨宠物混用。

## 四、一次对话的执行链路

```
审核 → load_context → retrieve → 记忆 → actor → validate → settle
```

| 节点 | 职责 | 产出 |
| --- | --- | --- |
| `审核` | 对输入做安全检查，拦截不合规内容 | 放行 / 拒绝 |
| `load_context` | 组装宠物人设、近期消息窗口，受 token（模型处理文本的最小计量单位）预算约束 | 上下文包 |
| `retrieve` | 查知识库，做 RAG（检索增强生成：先查资料再回答） | 带分数的资料候选 |
| `记忆` | 召回当前宠物的长期记忆：向量 + 关键词双路召回 → 名次融合 → 多信号排序 | top 8 条记忆 + 出处 |
| `actor` | 模型生成回复，并输出结构化的记忆提议 | 回复文本 + Proposal |
| `validate` | 校验提议的字段、归属范围、引用合法性 | 合法提议 |
| `settle` | 用确定性规则结算提议 | CommitPlan |

`settle` 是纯函数：相同输入永远得到相同的计划，不读写任何外部系统。它带来三个直接能力：离线单测、精确回放、事后审计。

Run 创建带 `client_request_id`，仓储层唯一索引保证同一条消息重发不会产生第二个 Run。每个 Proposal 携带 `generation`（代次：同一条消息被重新生成时的版本号），`settle` 校验代次，旧代次结果整体拒绝。

每个 Run 在创建时冻结版本四元组（VersionTuple：流程版本、提示词版本、模型路由版本、索引版本的组合）；每个节点写入带自增 `seq` 的 NodeEvent。最终任何一条回复都能回答"当时用的是哪版流程、哪个模型、哪版资料"。

## 五、长期记忆

### 5.1 数据分层

一条记忆就叫 **Memory**（记忆：从一段对话里提炼出的一句结论）；检索和拼 Prompt 都以它为单位。

| 实体 | 存储 | 含义 | 关键性质 |
| --- | --- | --- | --- |
| Episode（对话窗口） | `pet_episodes` | 一段连续对话的原始记录 | 只追加；窗口指纹唯一索引防重复抽取；是所有结论的证据 |
| Memory（记忆） | `pet_memories` | 从原文提炼的一句话结论 | 只追加；没有 `status / version / valid_from / valid_to / CAS`（比较并交换） |
| Source（出处边） | `pet_memory_sources` | Memory ↔ Episode 多对多 | 唯一键 `(memory_id, episode_id)`；支持数 = `count` |
| Stats（状态旁路） | `pet_mem_stats` | 可变状态单独放，不改 Memory 本体 | `use_count / last_used_at / pinned / deleted_at` |
| 向量投影 | Qdrant | 由 Memory 生成的索引 | 可删除、可重建；重建时过滤墓碑 |

`Memory.metadata` 保存 `refutes`（它否定了哪条旧记忆）与 `objective_memory_ids`（主观记忆锚定的客观记忆）。旧记忆的记录永远不改；变化通过"新增一条 + 指向旧记录"表达。

### 5.2 写入：批量门控 + 九步主链

回复结束后不逐轮写库。待写窗口在 `pet_write_tasks` 累积，满足任一条件才触发：攒够 3–10 轮、停聊 30–120 秒、最长等待 2–5 分钟、退出或切换宠物、到达预算上限。同一用户串行、不同用户并行，避免两条并发抽取把同一件事都判成 `NEW`。

```
AdvanceTurn → PersistEpisode → Extract → Validate
→ Reconcile → Commit → LinkSources → Project → Report
```

三层幂等：任务层用 `external_idempotency_key` 防重复投递；Episode 层用窗口指纹唯一索引防整段重抽；内容层用 `MD5`（内容指纹）`(record_kind + viewpoint + text)` 防同一条记忆重复写入。

### 5.3 抽取：模型只提议，代码说了算

- 客观记忆第三人称、可核验；主观记忆第一人称（"我知道主人去了杭州，有点想他"）。
- 一条不超过 50 字、只表达一个语义单元；两个断言拆成两条。
- `evidence_turns` 必须落在本批窗口内，`viewpoint` 与 `owner` 必须一致。
- `importance` 由模型按锚点档位给建议（0.2 闲聊 / 0.5 一般偏好 / 0.8 重要关系承诺 / 0.95 身份级），代码 `clamp`（夹到区间内）到 `[0,1]`，写入后不再改。
- 这段对话确实没有可记的内容时，返回空列表是合法结果，不是失败。

### 5.4 消解：只有三种判定

| 判定 | 含义 | 落库动作 |
| --- | --- | --- |
| `NEW` | 新记忆 | 新增 Memory + Source + 向量 |
| `DUPLICATE` | 与同泳道旧记忆等价 | Memory 不动，只把本批 Episode 挂到旧 Memory |
| `REFUTES` | 与旧记忆冲突 | 新增 Memory，`metadata.refutes=[旧 id]`；旧记录一个字段都不改 |

同一条泳道内按 `content` 向量召回 top 8 作为候选；没有候选直接判 `NEW`。模型只能在白名单里选目标 id：编造 id、调用失败、或目标是已被 refutes 的记录，一律回落 `NEW`——宁可多存，不可错覆盖。支持数用 `count(pet_memory_sources)` 实时算，不单独维护计数列。

### 5.5 三条泳道

| 泳道 | `viewpoint` | 含义 |
| --- | --- | --- |
| 客观 | `__world__` | 世界的共同认知，如"主人今天去了杭州" |
| 主人主观 | `user` | 主人的感受与态度 |
| 宠物主观 | `pet:<id>` | 宠物自己的理解，允许与客观不一致 |

三条泳道各自消解，绝不跨泳道；也不是每条记忆写三份——只有该视角确实有独立语义时才写。能脱离具体事件独立成立的（偏好、厌恶、身份、关系、习惯、承诺）放客观；必须挂在具体事件上的感受、态度、期待放主观。主观记忆用 `metadata.objective_memory_ids` 锚定客观记忆，跨视角只附加、不参与排序。

### 5.6 纠正、删除与隔离

- **纠正**：走 `REFUTES` 新增一条，旧记录不改；注入 Prompt 时保留时间线并标注"已被纠正"，这样宠物能解释"我当时以为是 A，后来你说其实是 B"。
- **删除**：写墓碑（`pet_mem_stats.deleted_at`）→ 删向量 → 解 Source → 清孤儿 Episode → 删 Memory 本体；只保留 `memory_id + deleted_at` 墓碑。每一步可重入、可重试；重建索引时过滤墓碑，删掉的记忆不会复活。
- **删除整只宠物**：Source → Stats → Memory → 向量 → 媒体文件。
- **隔离**：每只宠物独立记忆域，过滤条件在召回前进入 Qdrant payload 与 BM25 语料范围。

## 六、混合检索

| 阶段 | 做法 | 关键参数 |
| --- | --- | --- |
| QueryExpand（查询扩展：把带代指的原句补全成若干检索表达） | 原句 + 最多 2 个改写；原句必留一路 | 超时 3 秒回落原句 |
| Dense（稠密向量：把文本压成固定维度数字，语义相近则距离近） | Qdrant 向量召回，payload（随向量存储的过滤字段）前置过滤 `user_id / pet_id / viewpoint` | 每路 30 条 |
| Sparse（稀疏关键词：按词是否出现及权重表示文本） | BM25（经典关键词相关性打分，综合词频、逆文档频率与文档长度），中文用字符二元组 | 30 条；`k1=1.5`、`b=0.75` |
| 融合 | RRF（倒数排名融合：只用名次换算分数再相加），再按上限归一化 | `k=60`；`ceiling=2/61`；top 40 |
| 排序 | 多信号加权 | top 8 进 Prompt |
| 跨视角 | 命中客观附加相关主观，命中主观附加关联客观 | 只附加，不参与排序；上限 5 |

```
score = 1.00*语义 + 0.20*保持度 + 0.15*重要度 + 0.10*时间
排序键 (score, 语义) 降序
```

四个信号：

| 信号 | 来源 | 说明 |
| --- | --- | --- |
| 语义 | Dense + BM25 两路 RRF，`normalized = raw / (2/61)` | 归一到 `0~1`，不是余弦分 |
| 保持度 | `retention = exp(-age_days / S)` | 艾宾浩斯式衰减：常用、分散在不同的日子用、证据多，`S` 变大，忘得更慢 |
| 重要度 | `Memory.importance` | 抽取时定，写入后不改 |
| 时间 | 与提问时间窗的匹配度 | 无时间意图给 0.5；窗口内 1.0；窗口外按距离衰减；高置信时间查询直接硬过滤 |

```
S0 = 3 + 30*importance
S  = S0 * (1+0.6*ln(1+u)) * (1+0.08*min(d,5)) * (1+0.10*ln(1+e))
retention = exp(-age_days / S)
```

`u` 是实际使用次数，`d` 是不同自然日使用天数，`e` 是支持它的不同 Episode 数。保持度只做排序信号，不直接决定删除；容量淘汰是独立策略。

两点容易讲错：

- **同一 Memory 被多个子查询命中时取最高归一化分，不累加**；否则改写越多，分数越高。
- **排序完全在应用内完成**：四个信号都有明确来源，结果可复算；权重和是 1.45，语义约占 69%，是决定性项，其余三项只做小幅修正。

**隔离发生在召回前**：Dense 在 Qdrant payload 上按 `user_id / pet_id / viewpoint` 过滤；BM25 只在当前范围的 Memory 语料上打分。不会出现"先全库召回、再在 Python 里筛掉别的宠物"。

## 七、可靠异步

回复发出后，记忆抽取、三判定消解、索引投影由 Worker 异步执行。任务队列存放在 MongoDB，状态机如下：

```
pending ──claim──> running ──complete──> done
                      │
                      ├──fail（可重试）──> pending（退避后重试）
                      └──fail（不可重试）──> dead
```

| 机制 | 作用 |
| --- | --- |
| 幂等键唯一索引 | 同一业务动作只入队一次；重复提交被数据库挡住 |
| Lease（租约：领取任务时获得的限时工作凭证） | Worker 崩溃后任务不会永久停在 running |
| Heartbeat（心跳续租） | 按租约一半周期续期，区分"还在干活"与"已经死了" |
| Fencing Token（栅栏令牌：每次领取生成的新编号） | complete / fail / renew 都校验当前 token，旧 Worker 复活后无法提交 |
| Reconcile（对账：定期扫描超时任务并重新入队） | 兜底回收过期 running 任务 |
| Effect 幂等键 | 每个副作用独立幂等，重试不会做两遍 |

租约、心跳、栅栏令牌三者同时存在，才构成"崩溃可恢复、结果不重复"的闭环。只有租约没有栅栏令牌时，旧 Worker 与新 Worker 可能同时认为自己有权提交。

## 八、流式交付

```
POST /v1/runs              → 202 { run_id }
GET  /v1/runs/{id}/events  → text/event-stream
```

SSE（Server-Sent Events：服务器通过一条 HTTP 连接持续向下推送事件）事件带自增 `id`。客户端断线后携带 `Last-Event-ID` 重连，服务端从断点续传。

客户端解析器处理三类异常输入：

| 情况 | 处理 |
| --- | --- |
| 半包：一个事件被网络切成两段 | 维护文本缓冲，只在空行（事件分隔符）处切帧 |
| 中文跨片：一个汉字 3 字节，可能切在中间 | 使用流式 UTF-8 解码器，不完整的尾部字节留到下一片 |
| 心跳注释：`: ping` | 识别注释行并忽略，不当作事件解析 |

重连采用指数退避（`400ms × 重试次数`，上限 2.5 秒）；收到真实事件后重试计数清零；401 先刷新登录态再重连。客户端断开 SSE 不等于任务取消，取消通过 `POST /v1/runs/{id}/cancel` 显式发起。

## 九、流量治理

- **令牌桶（Token Bucket：按固定速率补充令牌，请求消耗令牌，允许短时突发）**：Agent 流量天然突发，令牌桶既能吸收突发，又有总量上限。
- **429 + `Retry-After`**：超限时明确告诉客户端等待多久，避免无脑重试造成雪崩。
- **取消语义**：取消是"请求停止"，正在执行的模型调用不一定能瞬间中断，但会在下一个可中断点退出，并且不再执行后续副作用；事件流会明确标记本次以取消结束。
- **背压（Backpressure：下游处理不过来时主动拒绝，而不是无限排队）**：连接数与在途任务数都有上限，超过即拒绝，避免排队耗尽内存。

## 十、工程架构与质量

### 10.1 端口-适配器

`domain/ports.py` 定义全部 Protocol（协议：只描述能力、不绑定实现的接口约定）。业务层只依赖 Protocol；MySQL、MongoDB、Qdrant、Redis、百炼分别由独立适配器实现。测试中使用内存实现，绝大多数用例不需要启动容器。

模型接入同样走端口：对话、向量、离线素材生成是独立适配器，模型名与路由由配置驱动，替换模型不影响业务层。

### 10.2 确定性优先

- 能用确定性规则解决的，不交给概率模型。
- 必须由模型做的语义判断，把答案空间约束到固定标签或固定 schema（字段结构）。
- 模型失败时有明确的降级路径，不把"模型不可用"扩散成"整条链路失败"。

### 10.3 版本与审计

- Run 创建时冻结 VersionTuple。
- 每个节点写入 NodeEvent（`seq` / `node` / `type`）。
- 每个副作用携带幂等键。
- 任务状态迁移保留 lease token 与失败原因。

### 10.4 存储职责

| 存储 | 数据 | 丢失后的后果 |
| --- | --- | --- |
| MongoDB | 消息、Memory、出处、事件、队列 | 权威数据丢失，不可再生 |
| Qdrant | 向量索引 | 可从 Memory 重建 |
| MySQL | 账号、宠物档案 | 权威数据丢失，不可再生 |
| Redis | 限流计数、短期状态 | 可重建，不影响权威数据 |
